# Design pressure from the first public dogfood

This table records what the real correction episode did to the kept M8 ideas.
It is evidence about a Zone 3 adapter, not a normative format decision.

| Concern | Outcome | Cost and consequence |
| --- | --- | --- |
| Exact source snapshots | Supported | Eight MIT-licensed blobs fit unchanged in a closed bundle. Source identity remained simple and useful. |
| Exact evidence spans | Supported with adaptation | Marker-based capture had to resolve to byte and line ranges and span hashes. One marker diagnostic exposed the need for explicit ambiguity rules. |
| Assertion revision | Required adaptation | M8's integer fact revision was too narrow. The adapter uses scoped natural-language statements while preserving predecessor linkage. |
| Recorded-as-of reconstruction | Supported | H1 remains stable after H2 and resolves the earlier assertion revision. This was the clearest benefit over a prose report. |
| Event, Git, availability, and record time | Required adaptation | A single timestamp would have produced a false history. The profile keeps these meanings separate and leaves event time unknown. |
| Assessment | Partly useful, still over-shaped | Scoped limitations and closed-file absence are valuable, but the episode does not justify general assessment or policy machinery. |
| Open question | Missing from M8, clearly useful | The absent incident report needed a first-class unresolved question with a declared closure basis. |
| Acceptance decision | Correctly omitted | No actor or policy accepts the technical claims. Adding a decision would have collapsed evidence and authority. |
| Closed-world absence | Required adaptation | Statements about missing locks or reports are valid only against an explicit complete file set. The adapter records that basis. |
| Projection rebuild | Supported | Three outputs rebuilt byte-for-byte from the bundle after exact deletion. |
| Generated Markdown style | Required integration policy | The exact dossier has a harmless double blank rejected by hand-editable Markdown lint. Generated bytes remain governed by rebuild and link checks. |
| Ordinary search baseline | Strong but incomplete | Eight `rg` queries answered two tasks cheaply. The fixed context missed helper-body safeguards, while GraphTruth retained their exact support. |
| Capture ergonomics | Main weakness | The 27-event JSON declaration is auditable but too manual for routine use. Incremental capture and review tooling is the next practical need. |
| Generic runtime claim | Not supported | The adapter is episode-specific. Promoting its shapes to schemas, RFCs, or the default runtime would be premature. |
| Decision contract | Failed to classify the observed win | Requiring all baseline cells to pass made `keep` impossible when GraphTruth alone passed a cell. Future comparisons must separate cell validity from branch success before freezing thresholds. |

## What survives a shrink

The episode directly supports the predeclared subset:

- byte-exact source snapshots and closed inventory;
- exact evidence spans;
- additive assertion revisions;
- distinct source and recorded horizons;
- an explicit open question.

These pieces produced all three maintained structural benefits. Assessment
records helped render limitations but did not yet prove that their richer
shape belongs in a reusable runtime.

## Next engineering implication

If the owner chooses `shrink`, the next useful implementation should be a
small incremental capture interface for that subset, exercised on a second
fresh public correction. It should not generalize the current JSON shapes into
Zone 1 or Zone 2. If the owner chooses `stop`, the next work should first repair
the experimental decision model, then select a fresh episode.
